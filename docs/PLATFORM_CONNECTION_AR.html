كيف تتصل المنصة بالوركفلو؟

العودة إلى شرح العقد

المستخدم يتعامل مع الموقع. الخادم المحلي يحفظ الملفات ويستخرج النص، ويرسل JSON إلى n8n. الوركفلو يتحقق ويحلل ثم يعيد نتيجة مرتبطة بنفس المطالبة والوظيفة والإصدار.

الرحلة بلغة المستخدم

يفتح المستخدم اختصار IntelliSure، وينشئ حسابه في أول مرة ثم يدخل باسم المستخدم وكلمة المرور. بعد رفع مستندات المطالبة معًا يضغط بدء التحليل. تظهر النتيجة والأدلة، ويمكنه التصحيح بسبب مكتوب وإعادة التحليل بإصدار جديد.

الدخول الآن بجلسة Cookie محلية، وليس بإدخال API Token من الطرفية. رموز الخدمات الداخلية منفصلة ولا تظهر للمستخدم. إكمال إنشاء الحساب الحقيقي يفعله المستخدم بنفسه.

1 — حفظ واستخراج المستندات

الموقع يحفظ الأصول في data/uploads، والسجلات والوظائف والتاريخ في data/app.sqlite3. Python يستخرج نص PDF النصي قبل إرسال الطلب. الصور بلا OCR تُحال للمراجعة اليدوية. الحقول المستخرجة محدودة بأنماط التنفيذ الحالية ولا تُعد تحققًا من صحة المستند.

2 — إرسال الطلب

POST http://127.0.0.1:5678/webhook/insurance-web-intake

يصل إلى Web App Intake، مع Header Auth محفوظ في اعتماد Insurance Local Web Intake. يستخدم الخادم N8N_OUTBOUND_TOKEN داخليًا؛ لا يُلصق المستخدم هذا الرمز في الواجهة.

المدخل يحمل schema_version وevent_id وjob_id وclaim_id وclaim_version وcorrelation_id وclaim_data، إضافة إلى evidence وdocument_flags. هذه المعرّفات تربط النتيجة بالمطالبة الصحيحة.

3 — التحقق والتحليل

يربط n8n بيانات الطلب بسياسة PostgreSQL، ويحفظ أسباب المراجعة ويجري التحليل الأولي. الطلب القادم من المنصة يمر عبر Local Advisory Analysis، فلا يستدعي Basic LLM Chain1 أو نموذجًا خارجيًا. لا يصدر قرار قبول أو رفض تأمين آلي.

4 — إعادة النتيجة

POST http://127.0.0.1:8766/api/integrations/n8n/result

Deliver Web Result يرسل case_id وjob_id وresult. المصادقة باعتماد Insurance Local Result Callback، باستخدام N8N_CALLBACK_TOKEN داخليًا. الخادم يطابق الوظيفة والإصدار، ويحفظ النتيجة والتاريخ ويجعل الحالة review.

تكرار callback المطابق لا ينشئ نتيجة ثانية؛ التكرار المتعارض أو الإصدار القديم يُرفض. عقدة HTTP تحاول حتى ثلاث مرات، والخادم يملك وظيفة إرسال دائمة بمحاولات محدودة عند تعطل المعالجة.

5 — العرض والتصحيح

المتصفح يقرأ API الموقع بجلسة HttpOnly وSameSite، ويستخدم CSRF للكتابة. الحساب يحدد صلاحية المراجعة على الخادم. يعرض المصادر والإصدارات، ويسجل اسم صاحب التصحيح وسببه. لا تتصل الواجهة مباشرة بقاعدة PostgreSQL.

ما دور Webhook القديمة؟

/webhook/insurance-claim-intake هي نقطة الإدخال القديمة المحفوظة. ليست عنوان المنصة الجديد، وبلا headerAuth في إعدادها الحالي. لا تنشر الخدمة على الإنترنت بهذه الإعدادات. نسخة الشرح تحتوي المسارات نفسها لكنها غير مفعّلة ولا تستقبل طلبات الإنتاج.

حدود يجب ذكرها في التسليم

تشغيل محلي لهذا الكمبيوتر. لا OCR حاليًا، ولا استخراج عام مضمون لكل الوثائق، ولا إغلاق كامل لمهام PostgreSQL من الواجهة، ولا اعتماد إنتاجي نهائي لمجرد وجود حساب دخول. وجود PDF سياسة ليس بديلًا عن مصدر سياسة موثق.

لا يحتوي هذا الملف على كلمات مرور أو قيم رموز. لا ترسل ملفات local-config.json أو webhook-credential.json عند مشاركة الشرح.
